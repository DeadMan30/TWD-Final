## Current target

1. Scale verified C/C++ replacements across `game/engine/` (Telltale core types, containers, math, and embedded Lua 5.x helpers) using the MSVC byte-exact matcher (`tools/verify.py match`) and Win64 live capture/hook-swap runner (`tools/win64_recorder/`).
2. Expand [runtime/](runtime/) Win32->POSIX/Android PAL coverage toward `WinMain` (`GetModuleFileNameW`, `CreateSemaphoreW`, `LoadLibraryW`) and Vulkan / GameActivity bring-up on `arm64-v8a`.

## Recent results

- Verified **10** `engine` functions (`619` bytes, `5,604+` call sites in `WalkingDead4.exe`) end-to-end with unit edge cases, mutant kills, MSVC `14.44.35207` `100.00%` byte-exact matching on `3` functions (`engine_meta_op_register`, `engine_meta_op_find`, `engine_rbtree_rotate_right`), live in-game capture replay (`tools/verify.py replay`), and live `twdgame.dll` hook-swap execution inside running `WalkingDead4.exe`.
- Expanded [runtime/](runtime/) PAL (`pal.c`, `hooks.c`, `platform_host.c`, `platform_android.c`) with monotonic QPC/ticks, recursive mutexes, TLS, `VirtualAlloc`/`Heap*`, events, POSIX/Win32 file I/O, and UTF-8<->UTF-16 adapters (`49` `KERNEL32.dll` imports + `138` bundled middleware imports = `187 / 556` PE imports mapped).
- Wired `tools/boot_harness.py` -> `symbols/boot.json` tracking PE startup readiness up to `WinMain` (`0x14002f7b0`).

## Known issues

- `309` thunks in `.text` are intentionally excluded by `tools/ghidra/ExportFunctions.java`; `114` remaining functions (`0.30%`) are currently unattributed in `symbols/source_files.csv`.
- Remaining OS/graphics imports (`USER32.dll`, `d3d11.dll`, `WS2_32.dll`, `ADVAPI32.dll`) are not implemented in `runtime/` yet; `WinMain` currently stops at `GetModuleFileNameW`.
